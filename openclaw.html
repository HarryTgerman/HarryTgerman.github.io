OpenClaw — production extensions

Author of the Agent Builder Playbook. Production deployment across the deflation.ai tenant fleet.

OpenClaw is an open-source agent platform. This page is about my production work on it: the Agent Builder Playbook I author and maintain (the patterns that turn vanilla OpenClaw into deterministic, domain-specific agents) and the plugin / channel / extension layer that makes it serve paying customers at deflation.ai.

The patterns below were discovered building production agents — back-office automation, sales pipeline, bookkeeping — and apply to any specialization. They live in the playbook as a 19-section guide that I keep current as new failure modes surface in production.

The Agent Builder Playbook

What I author and maintain. Three parts.

Part I · OpenClaw internals

  • Architecture — gateway, workspace, sessions, and how the system prompt is assembled.
  • The agent loop — message flow through the system, what triggers what.
  • Tools — how the agent calls external code, tool profiles, sandbox, and custom tools.
  • Memory & context — session memory, persistent memory files, compaction, and what survives context resets.
  • Skills — routing, skill format, on-demand loading, skill design.
  • Hooks & automation — event-driven automation, cron jobs, heartbeat, boot-md.

Part II · Agent design patterns

  • Identity priming — give an agent a professional role and it follows professional patterns. The cheapest production move.
  • Process rules — embedding deterministic workflows inside a probabilistic system.
  • Context budgeting — what to put where; avoiding "lost in the middle" pathologies.
  • Lifecycle — bootstrap → onboard → operational.
  • State management — CSV-based state, entity-per-folder, S3 as the source of truth. Survives context resets.
  • Heartbeat design — proactive behavior between conversations.
  • Instruction compliance — making LLMs actually follow your rules in production.
  • Testing & verification — tool verification, scenario testing, test infrastructure.
  • Localization — template markers, multi-locale deployment.
  • Anti-patterns — what doesn't work and why.

Part III · Platform extensions

  • Media handling — Gemini Flash preprocessing of files before they reach the agent, so the agent works on structured input rather than raw documents.
  • Native channels — registering email, SMS, and custom channels as first-class citizens with the same lifecycle as built-in capabilities.
  • Plugin architecture — building OpenClaw plugins: hooks, channels, routes, tools — the extension layer that makes the platform composable for domain-specific products.

Production deployment

Every deflation.ai tenant runs this OpenClaw deployment, hardened with the playbook patterns above. Tenants are isolated as Linux users on shared Hetzner VPS, hold zero external credentials, and talk only to the LLM gateway middleware (which enforces per-tenant inference budgets at HTTP-protocol level).

The deployment is composable: a tax tenant and a real-estate tenant run the same OpenClaw build with different product-template + tenant-leaf layers — the playbook patterns let the same base agent specialize without code forks.
